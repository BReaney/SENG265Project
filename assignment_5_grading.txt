Usability: 3/10 points.
Password field at login is not censored like password fields typically are. Login button should also be the largest button on the screen.
When no blogs exist, window is entirely empty, with no definite confirmation that the system contains no blogs.
When searching for blogs by name, there is no back button on the results screen, forcing the user to close and restart the entire application.
Program crashes and contradictory/illogical behaviour (success popup when in a failing state, posts with no content created, etc.) occur when text fields are left empty when submitting forms in many interfaces.
When blogs are created, values are stored incorrectly (name replaces the email field). Updating blogs works as intended.
"Change Blog Data" and "Edit Blog" are similar vague statements that introduce confusion as to their functionality.
The interface for deleting posts references Blog IDs, and the feedback the user receives on deletion is not clear.
Post timestamps are not in a human-readable format.
No validation checking for URL and email formats when creating blogs.
